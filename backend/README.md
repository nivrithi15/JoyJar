# JoyJar backend

Express, Cloudinary, and JWT API for saving small joyful memories. A memory belongs to the signed-in user and can include one optional image.

## Installation

1. Install [Node.js](https://nodejs.org/) (version 18 or newer is recommended).
2. In a terminal, enter the backend folder and install dependencies:

   ```bash
   cd backend
   npm install
   ```

3. Create a Cloudinary account, then copy the cloud name, API key, and API secret from its dashboard.
4. Fill in `backend/.env`:

   ```env
   JWT_SECRET=use-a-long-random-secret-here
   CLOUDINARY_CLOUD_NAME=your-cloud-name
   CLOUDINARY_API_KEY=your-api-key
   CLOUDINARY_API_SECRET=your-api-secret
   CLOUDINARY_UPLOAD_PRESET=your-optional-upload-preset
   PORT=5000
   ```

6. Start the development server:

   ```bash
   npm run dev
   ```

For production-style execution, use `npm start` instead. The API and JoyJar pages will be available at `http://localhost:5000` by default. Open that address (rather than opening the HTML files directly) so photo uploads reach the Cloudinary endpoint.

## Authentication

Register or log in first. Both endpoints return a JWT. Send it with every memory request:

```http
Authorization: Bearer <your-token>
```

## Important: temporary storage

JoyJar has no database. Users and memories are stored only in the server's memory, so **all accounts and memories are deleted whenever the server restarts**. Cloudinary images are still uploaded and can be removed through the delete endpoint while the server is running.

## API documentation

| Method | Endpoint | Auth | Description |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | No | Create an account |
| POST | `/api/auth/login` | No | Get a JWT |
| POST | `/api/memories` | Yes | Create a memory; accepts an optional image |
| GET | `/api/memories` | Yes | List the current user's memories, newest first |
| GET | `/api/memories/random` | Yes | Get one random memory |
| DELETE | `/api/memories/:id` | Yes | Delete one of the current user's memories and its Cloudinary image |

Valid categories are `little-win`, `someone-made-me-smile`, `something-beautiful`, `something-i-enjoyed`, `something-silly`, and `just-because`.

Image responses include `imageUrl` (the Cloudinary original URL), `thumbnailUrl` (300×300), and `polaroidUrl`. The last two are generated by Cloudinary transformations and are not separately stored.

`POST /api/upload` accepts an `image` multipart field and is used by `joyjar.html`. It returns original, thumbnail, and polaroid Cloudinary URLs.

## Postman examples

### Register

`POST http://localhost:5000/api/auth/register` with **Body → raw → JSON**:

```json
{
  "name": "Asha",
  "email": "asha@example.com",
  "password": "joyful-password"
}
```

### Login

`POST http://localhost:5000/api/auth/login` with **Body → raw → JSON**:

```json
{
  "email": "asha@example.com",
  "password": "joyful-password"
}
```

### Create a memory with an image

`POST http://localhost:5000/api/memories`

Set the Authorization tab to **Bearer Token** and paste the token. In **Body → form-data**, add:

| Key | Type | Example |
| --- | --- | --- |
| `text` | Text | `My plants grew a new leaf today!` |
| `category` | Text | `something-beautiful` |
| `image` | File | Choose an image (optional) |

The successful response includes `milestoneUnlocked`. It is `true` at 5, 10, 25, and 50 memories; then the response also includes the milestone's name.

### List, random, and delete

With the same Bearer token:

```http
GET http://localhost:5000/api/memories
GET http://localhost:5000/api/memories/random
DELETE http://localhost:5000/api/memories/<memory-id>
```

## Notes

- Images are limited to 5 MB and must be image MIME types.
- Cloudinary files are stored in the `joyjar/memories` folder.
- Keep `.env` private. It is ignored by Git; use it only for local secrets.
